# Realtime server

`server/` (Node 20+, `ws` + `ethers`). Carries **presence and chat**, and stores **room documents** signed by their owners (`rooms.js`). Ownership, items and money live on Monad; the server never holds funds or signs anything. If it is down, nobody loses anything: the client falls back to walking the town alone with the NPC residents.

## Run

```bash
cd server && npm install      # once
node index.js                 # ws://localhost:8767, GET /health for counters
npm test                      # smoke (chat, identity, rooms, check-in, hotel), venues (check-in, upgrades, lock, perks, facades, usernames, freeze and fall back, inventory, basement, hotel numbers, Exhibition), migrate (every older numbering and the old Homes), units (wall units, basement, no server), games, exhibition, shop: a mock chain, no network needed except the RPC stand-in
```

Env: `PORT`, `RPC_URL`, `NFT_ADDR`, `ALLOWED_ORIGINS` (comma list; empty = any, dev only), `MAX_PLAYERS`, `MAX_PER_IP`, `DATA_DIR` (reports, rooms, inventories; default `server/data`), `ROOM_PREP_MS` / `ROOM_SAVE_MS` (min time between room signatures / saves), `CHECKIN_IP_MAX` (check-ins per address and day, default 5), `VENUE_MS` (min time between room requests per player, default 1000), `HOTELINFO_MS` (how often the town signs are refreshed, default 10000), `SHOP_ADDRESS` (the deployed ChogShop; empty = the shop is "opening soon"), `SHOP_MOCK=1` (local tests only: purchases recorded in `DATA_DIR/shop/`; never on the live server). The page connects to `ws://<host>:8767`; override with `?server=ws://...`. Preview config `town-server` is in `.claude/launch.json`.

## Deployed (2026-10-08)

Fly.io app `chog-town-ws`, Frankfurt, one `shared-cpu-1x` 256 MB machine that never sleeps (about $2.5 a month plus cents of egress). Address: `wss://chog-town-ws.fly.dev` (`/health` for counters). Config in `server/fly.toml`; the Dockerfile runs as user `node`. Measured from the dev machine: chat A to B about 50 ms, position relay one tick (100 ms).

- Deploy: `flyctl deploy --ha=false --remote-only` from `server/`. `flyctl` is installed in `~/.fly/bin` (not on PATH). `--ha=false` matters: the default would start two machines, and players on different machines would not see each other (the server is single-process by design).
- A deploy onto a machine that crashed past its restart limit leaves it stopped: `flyctl machine start <id>`.
- Logs: `flyctl logs`. Reports are also printed there (`report {json}`), because the container disk is lost on every deploy.
- The live page picks this server automatically (`net.js`); locally it uses `ws://localhost:8767`, and `?server=` overrides both. `ALLOWED_ORIGINS` in `fly.toml` allows only `https://chog-hotel.pages.dev` and `http://localhost:8766`. This stops other websites from using the server from a visitor's browser; it is not authentication (a script can fake the header). Add any new page address there and redeploy.
- Source of the deployed code: private GitHub repo `boranoyundaa-cmd/chog-town-server` (only `server/`).
- Why a server at all, and why not on-chain: Monad is 300 ms blocks / 600 ms finality (July 2026, MIP-12); 100 players at 10 position updates a second would be 1,000 tx/s, a tenth of the chain's design capacity, each paying gas and a signature. Chat could technically go on-chain but every line would be permanent and paid. Ownership and money stay on-chain.

## Protocol (JSON frames; `server/index.js` header is the source of truth)

Client to server: `auth {addr, sig}` or `auth {session}`, `appear {token|null}`, `logout`, `move {x,z,ry,mv}` (~10/s), `chat {text}`, `report {id, reason}`, `enter {space, id?, level?, x, z, ry}`, plus the room (`checkinprep` / `checkin`, `upgrade`, `reactivate`, `roomlock`, `invget`, `venueprep` / `venuesave`...), game, Exhibition and shop frames below (the header of `server/index.js` is the full list).
Server to client: `welcome` (id, challenge, current players, `rooms:1` when the server knows rooms), `join`, `leave`, `appear`, `state` (batched moves, 10 Hz, only players that moved), `snap`, `chat`, `sys`, `authed`, `authfail`, `entered`, `roomfail`, `roomdoc`, `hotelinfo` (to the town).

## Mini-games (`server/games.js`)

Score book and match referee, persisted to `DATA_DIR/games.json`. Frames `g_*` (header of the file lists them). Identity = wallet, else the guest id the page keeps in `localStorage` (`g_hello {gid}`). Record games (`stack`, `rhythm`, `daily`) send only the result through `g_score`; limits: stack 0-80 floors, rhythm 20-400 notes and the score is computed from the counts, Daily Chog once per UTC day for today's date, 15 s between submissions. Two-player games (`rps`, `dance`, `c4`, `ls`) run on the server: simultaneous picks are revealed together, moves are validated, timeouts and quits decide. Boards: daily (UTC) and weekly (from Monday), top 10 and your rank; the same two players count at most 5 wins a day. Rewards: no tokens; at most one trophy per game per identity per day (a win against a resident in the browser counts for the trophy only, not the boards), five badges. Both `ENGINE` copies (server and `prototype/js/games.js`) must stay identical.

## Exhibition (`server/exhibition.js`)

Weekly room contest, Monday 00:00 UTC to Sunday 24:00, with a theme. Frames `ex_list`, `ex_prep` / `ex_submit` (signed entry: a snapshot of your saved room, from `hotel.docs`, kept with its size and replaceable until Sunday 12:00 UTC; replacing with a different room clears its votes), `ex_voteprep` / `ex_vote` (one signed vote per wallet per week, never for yourself, only wallets with a saved room, movable until Sunday 24:00; counts hidden until you voted, public once the week is over). The winner (a tie goes to the earlier submission, no winner without a vote) gets a trophy and heads the next week. `enter {space:'hotel', floor:'E'}` is the floor, `enter {space:'exhibit', id}` one entry (read-only). Persisted in `DATA_DIR`.

## Shop (`server/shop.js`)

The server never holds funds or signs. It reads what a wallet owns in the ChogShop contract (`balanceOfBatch`, cached; `shopget`, `shopnotice {tx}` after a purchase forces a fresh read) and enforces what that allows: decor pieces in saved rooms (`room_catalog.json` entries with `shop`), cosmetics worn in extra slots (`equip`, `cos` in every player record), venue budget extras, events (`eventstart`, 24 h, announced in lobby and town), the security camera (`camopen` / `camclose`, a live window of the venue), and tips (`tip {venueId, amount, tx}` checks the `Tip` event of the transaction, then announces it). **Tier locks are enforced here**, not on chain. Catalog: `shop_items.json`, built by `tools/build_shop_catalog.js` from `contracts/items.json`. Contract and deploy: `contracts/README.md`; the owner deploys and sets `SHOP_ADDRESS`.

## Spaces and rooms

Every player is in exactly one **space**: `city` (the town, default on connect), `solo:<id>` (a private unsaved spot: a walletless guest's temporary room), `hotel:<floor>` (0 = lobby 16.5 x 12 m; 1.. the 24 x 24 m halls; **-1.. the basement** (B1..); `E` = the Exhibition floor), `venue:<id>` (a Hotel room, free or a holder's: the document comes from `seed_venues.json` or the owner's signed save; `venue:<id>#2` is the upper level of a two-level venue, a space of its own, so presence and chat are per level) or `exhibit:<id>` (a contest entry, read only). Presence, movement, chat and `appear` only reach players in the same space; walking limits are per space (town slab 64 x 64 m, `CFG.half` 32 = `HALF` in `world_city.js`, or the room floor). `enter` changes space and answers `entered {space, owner, mine, doc, savedAt, floor?, venue?, players}`. **Rooms are public unless locked**: the Home space (`room:<wallet>`), invitations and share links no longer exist; `enter {space:'room'}`, `roomprep`, `roomsave`, `invite` and `invlink` still answer (a note, nothing else) so an old client does no harm. **There is no capacity limit.** A client that does not see `rooms:1` in `welcome` (older server) plays rooms locally; `hotel:1` says the server knows the hotel. **Update the `COPY` line of the `Dockerfile` whenever the server gets a new file.**

`hotelinfo {}` answers `hotel {floors, basement, venues, counts}`: `floors` is the highest above-ground floor, `venues` the above-ground rooms only (**the game's venues and holders first, free rooms below**, no room documents), `counts` the people inside each room, pushed to players on hotel floors every 2 s when it changed. `hotelfloor {floor}` answers `facades {floor, items}` (a basement floor adds `rooms`). **`hotelinfo` the other way** (server to every player in the town, on connect, on entering the town, and when it changes, checked every 10 s): `{t:'hotelinfo', floors, basement, rooms, busiest:{door,name,inside}|null, events:[{door,name,title,until}], winner:{name,by}|null}`; `rooms` counts every room including the basement, `winner` is last week's Exhibition winner (the room's name).

Saving (`venueprep {doc, level?}` returns the cleaned document's hash message and a timestamp, the wallet signs it, `venuesave` is stored only if the signature recovers to the signed-in wallet, matches the cleaned document and is under 2 minutes old; the free room is saved the same way as a venue). The document is rebuilt from `room_catalog.json` (pieces, themes, window views, patterns; **generated from the game data: `node tools/build_room_catalog.js` after any catalog change**) with the **room's budget** (free 80 pieces and 10 lights on 14 x 10 m; a venue gets its tier's), text cleaned, pieces with `minTier` or venue-only pieces dropped where the tier does not allow them, shop pieces the wallet does not own dropped, **wall pieces put on their back wall** (`ry` 0 or 90, `z = -D/2` or `x = -W/2`). A save is broadcast to the visitors inside as `roomdoc`, takes the pieces it places again out of the inventory (`inventory.consume`), and renames a free room after its document. Frames are limited to 2 KB, except the room documents (16 KB).

**Persistence (live since 2026-10-08).** Rooms live in `DATA_DIR/venue_docs/` (and `venue2_docs/`, `facade_docs/`; the old Homes in `rooms/` are moved to `rooms_old/` by the first start of the rooms server); on Fly that is the 1 GB volume `chog_data` mounted at `/data` (about $0.15 a month, daily snapshots kept 5 days; one machine only, a volume belongs to one machine). The volume is mounted root-owned, so the Dockerfile starts as root, `chown`s `/data` and drops to `node` with `su-exec`. A live check (sign in, save, read back) passed; look at the files with `flyctl ssh console -a chog-town-ws -C "ls /data/venue_docs"`. Deploy the **server before the site**: a new site on an old server still works, rooms then stay local.

## Rooms, holder venues, usernames (rooms built 2026-10-15)

- **License** (`license.js`, data `license_data.json` built by `python tools/build_license_data.py` after `build_tokens.py` or `fetch_owners.py`): the server reads `balanceOf` and `ownerOf` on chain (the owner snapshot only says which tokens to check first; a stale snapshot triggers one batched scan of the collection), adds the points per token from the collection's `Tier` trait and gives the tier. Cached 10 minutes per wallet; a fresh read is made when the owner acts on it (upgrade, move).
- **Rooms** (`hotel.js`): the 12 seed venues plus **one record per wallet** in `DATA_DIR/venue_meta/<wallet>.json`: `tier` 0 (free room) to 4, `layout: 3`, `floor` (negative = basement), `unit` (first of the 8 wall units, 1 to 4 north, 5 to 8 west), `units` (1, 2, 4 or 8), `levels`, `no` (`floor * 100 + unit`, `-(|floor| * 100 + unit)` below ground), `size`, name, kind, description, `state` `closed`/`open`/`frozen`, `locked`, `lastEntered`, rule `public`/`holders`/`list`, guest and ban lists of usernames. The signed rooms and the facade are documents in `DATA_DIR/venue_docs/`, `venue2_docs/` (the upper level) and `facade_docs/` (`rooms.js` stores; the signed message says "venue", "venue upper level" or "facade", so signatures are not interchangeable). Templates (`TEMPLATES`, per level; table in `docs/game/world.md`): 0 = 14x10 m, 80 pieces, 10 lights, 1 unit, no facade; 1 = 22x16, 200, 16, 2 units, facade 20; 2 = 27x20, 300, 18, 4 units (a whole wall), 40, stage and DJ booth, music; 3 = 27x20, 280, 18, 4 units on two floors, 60, VIP upper level; 4 = 33x22, 340, 22, 8 units on two floors, 80, VIP upper level. Rooms are placed first-fit by `allocate` (a run of units on one wall; a penthouse goes above every smaller room; new floors on top as needed); a free room is created open and public, a record made by `activate` for a higher tier starts **closed**.
- **Check-in** (`checkinprep` -> `checkinprep {message, ts, has}`, `checkin {ts, sig}` -> `checkin {ok, already, no, floor, mine}`): the wallet signs a short message like a username claim; creates the free room; asking again returns the same room; at most `CHECKIN_IP_MAX` (5) new rooms per address and day (in memory, reset by a restart).
- **Upgrade** (`upgrade` -> `upgrade {ok, moved, no, floor, unit, units, from:{no,floor}, tier, mine}` or `{ok:false, code, reason}`; codes `no-room`, `tier-low`, `max`, `smaller`, `chain`, `busy`): the room size of the license's **current** tier (fresh read). `hotel.upgrade` grows it in place when the units next to it (same first unit) and the floor above are free, otherwise it moves to the first free run of the right length (its own old units count as free), otherwise a new top floor; `shiftDoc` + `fitDoc` carry the decor, a copy of the originals goes to `venue_backup/`; everybody inside is sent back to the hall (the room changed size). A tier rise never grows a room by itself. `venuemake {name, cat, desc}` is the same with a listing text; `venuemove` also upgrades, or **shrinks in place** to a lower tier (the first unit stays).
- **Holdings** (`hotel.reconcile`, at sign-in, on `venueinfo`, when the owner enters and every 6 hours): a venue whose owner fell below its tier is **frozen** (closed, decor kept, visitors sent out); it thaws if the tier returns; after 7 days it **shrinks in place** to the license's room, a free room when no Chog is left (first unit kept, the rest freed). Pieces that no longer fit (floor, budget, tier, venue-only, shop not owned) and the whole upper level go to the **inventory** (`inventory.js`, `DATA_DIR/inventory/<wallet>.json`, 400 pieces; `invget` -> `inventory {items, max}` with `locked: 'tier'|'venue'|'shop'` per piece that cannot be placed now; pushed again after changes).
- **Basement** (`hotel.sweepBasement`, at start and every day): a free room nobody entered for 30 days (`lastEntered` is set when anybody walks in, written to disk at most hourly) and with nobody inside moves to the first free unit of B1, B2... (8 units per floor); holder venues never move. `reactivate` -> `reactivate {ok, no, floor, from, mine}` moves it to the first free unit above ground or a new top floor. The directory never lists the basement; the elevator reaches it.
- **Lock** (`roomlock {locked}` -> `lock {ok, locked, mine}`): while locked only the owner can enter (checked first in `hotel.entry`, before the venue's own rules); people inside stay. The directory carries `locked`.
- **Migration** (on start): records and the 12 seed venues from the slot numbering become units (`unit = 2 * slot - 1`, `units = 2 * span`: door numbers follow the first unit, 101, 103, 105...), the first numbering (8 small slots, no `layout`) is re-placed oldest first, venues and Homes at pre-2026-10-15 sizes are shifted into the new rooms (`rooms.shiftDoc`: every piece keeps its place against the back walls), and **every old Home** (`rooms/<wallet>.json`) becomes a free room (20 x 15 shifted into 14 x 10, overflow to the inventory; a wallet that already has a venue gets its Home pieces in the inventory), the file moving to `rooms_old/` (`test/migrate.js`).
- **Entry** (`hotel.entry`, checked on every `enter {space:'venue'}`): the owner always; locked = refused; frozen/closed = refused; banned name = refused; `holders` = the player must appear as their own Chog; `list` = the player's username must be on the list; the VIP upper level has its own rule. Closing a venue sends visitors back to its floor.
- **Facade** (venues only): a document in a strip 10 m (Ser) or 20 m (a whole wall or more) wide and 1.6 m deep; a last rule drops pieces in front of or over the door and wall pieces on the side wall. Sent per floor (`hotelfloor {floor}` -> `facades {floor, items}`) and pushed to the floor when the owner saves.
- **Usernames** (`users.js`): `usernameprep {name}` / `usernamesave {name, ts, sig}`; 3 to 16 characters, starts with a letter, unique ignoring case, reserved and look-alike names refused, one change per 7 days. The username is shown on plates and in chat instead of "Chog #N" or "Guest-NNNN"; a free room without a name is called after it.
- Messages: see the header comment of `server/index.js` (the receptionist's client calls are also in `prototype/js/venue.js`: `VENUE.checkIn()`, `upgrade()`, `reactivate()`, `setLock()`, `loadInventory()`).
- Not built: an anti-rental holding period (decided against by the owner); `server/invites.js` is dead code (nothing requires it any more).

## Phone companion (`phone.js`, 2026-10-16)

- **Pairing:** a signed-in PC sends `phonekey {}` and gets `phonekey {code, exp}` (8 letters, one use, 10 minutes; Lev shows it as a QR code for `m.html#k=CODE`). The phone connects with `?phone=1` in the socket URL and sends `phonepair {code}` -> `phoneok {key, addr, name}`; later visits send `phoneauth {key}`. Keys last 30 days, a wallet keeps 3 (the oldest goes), stored hashed in `DATA_DIR/phone_keys.json`.
- **A phone is never a player:** its space is `phone:<id>` (nobody else's), the town never gets a `join`, and it may only send `phonepair`, `phoneauth`, `m_room` and `roomlock`; everything else is ignored.
- **Data:** `m_room {}` -> `m_room {room, doc, doc2, camera, inside, today:{visitors, tips}, events}` (`room` null without a room). With the security camera the phone gets the camera frames every second (players now carry `token` and `ry`, so it can draw the right Chog); without it `m_count {inside, today}` when the numbers change. Today's distinct visitors (the owner does not count) and tips are kept in memory per room and reset at 00:00 UTC or on a restart.

## Identity

1. Everyone is a **guest** on connect (default Chog, name `Guest-NNNN`).
2. To appear as Chog #N the wallet signs the server's challenge once (`personal_sign`, free, no transaction); the server recovers the address and checks `ownerOf(N)` on chain. A 12 h session token (kept in `localStorage`, held in server memory) skips the signature on later visits; a server restart means one new signature.
3. One window per Chog: a second login with the same token replaces the first.
4. Traits are not sent by the server; clients load them from the token id (`WALLET.traitsOf`).

## Anti-abuse (v0)

- Movement: positions are clamped to the island and to 1.6x walk speed; repeated violations get a `snap` back. **No building collision on the server yet** (a modified client can walk through walls).
- Chat: 140 chars, burst of 3 per 6 s, repeat text blocked, links and wallet addresses stripped (scam vector in a crypto game). **No word/profanity filter** (owner decision: adult, crypto-native audience); moderation is reports, auto-mute and local mute.
- Reports: written to `server/data/reports.jsonl` with the target's last 5 lines; 3 distinct reporters in 10 min auto-mute the target for 10 min. Players can also mute locally. Nobody reviews the file yet.
- Limits: 6 connections per IP, 200 players, 2 KB frames, Origin allow-list, a few check-ins per address and day.

## Not done
